finding was reproduced independently before any fix, against both this fork
and upstream rrule.js 2.8.0. Semantics were checked against RFC 5545
§3.3.10/§3.8.2.4, RFC 7529 and RFC 8984 §4.3.3.1 rather than taken from the
report. **All 15 were valid**, and all are fixed.

## Decisions on the report's open points

- **Leap seconds.** `BYSECOND=60` is accepted (RFC 5545 allows it) but never
  matches, because neither JavaScript nor Dart dates can represent it. A rule
  whose only BYSECOND value is 60 has no occurrences. Previously it rolled
  into the next minute.
- **Oracle independence.** `tools/verify/oracle.mjs` is a brute-force
  evaluator written from the RFCs. It uses its own calendar arithmetic, finds
  week 1 as the week containing January 4, and shares no code or masks with
  either package. It is now the primary check, run in CI on every change for
  the corpus and for fresh fuzz cases. It confirms all 7,408 corpus cases in
  its scope (DAILY to YEARLY with every BY* part, BYSETPOS and SKIP). The
  remaining 1,004 sub-daily cases are checked against python-dateutil, whose
  "spins on an empty rule" cases stay reported separately.
- **CI trigger.** The `verify` job now runs on every push and pull request.
- **JSCalendar DTSTART and COUNT** (RFC 8984: the start is always the first
  occurrence). This belongs to the caller. Mobile's recurrence code should be
  audited separately; the engine is unchanged here.
- **DST gaps and folds.** These stay with the adapter and its caller. The
  engine is floating by design.
- **Validation policy.** Values outside RFC 5545's ranges are rejected.
  Combinations RFC 5545 forbids but rrule.js evaluates (BYWEEKNO with
  non-YEARLY frequencies, for example) are still evaluated, for compatibility.
